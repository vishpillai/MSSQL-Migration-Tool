Configure up to 3 source / target pairs

Pairs run one after another. Databases within each pair run sequentially; each database is validated, migrated, post-checked, and its temporary backup deleted before the next begins.

Enter a hostname, SQL instance (for example, HOST\INSTANCE), or IP address. Validate checks SQL connectivity/version and shared-drive access before discovery.

Optional: after discovery, select databases and run Assess readiness only to check migration risks and download a report. This does not start a migration. The assessment is DMA-inspired, not the retired Microsoft DMA tool, and does not replace application testing.

Server disk usage

View used and free capacity for every volume on one or more SQL Server hosts. Green indicates less than 80% used, amber 80-89%, and red 90% or more. Connections use the web host's Windows identity and require permission to connect to SQL Server and read remote disk inventory.

Live server monitor

Monitor SQL health using transient 15-second snapshots. CPU, memory, disk capacity, and storage latency are graphed with rolling in-memory trends and threshold alerts; active requests and blocking are shown separately. Nothing from these snapshots is written to application logs, audit logs, or disk.

When a migration starts, its source and target instances are selected and monitored automatically. The web host identity needs SQL connectivity and server-state permission (VIEW SERVER STATE; SQL Server 2022+ may require VIEW SERVER PERFORMANCE STATE).
